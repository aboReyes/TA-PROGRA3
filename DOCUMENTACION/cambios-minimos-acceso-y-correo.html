2.1 Build de persistencia: faltaban TransaccionDAO y TransaccionDAOImpl

Síntoma: mvn package falla con cannot find symbol class TransaccionDAOImpl en DAORefactorChecks.java (línea 343).
Causa: el README de persistencia y el test usan esas dos clases, pero no están en ningún commit de develop. Patrón tomado del repo del profesor (2025-2, sesión 23: PersistibleTransaccional + TransaccionalBaseDAO).
Dónde: Avances/patitasarriba-persistencia/src/main/java/patitasarriba/

// dao/TransaccionDAO.java
package patitasarriba.dao;
import java.sql.Connection;
import java.sql.SQLException;
public interface TransaccionDAO<T, ID> extends DAO<T, ID> {
    void crear(T modelo, Connection conn) throws SQLException;
    void actualizar(T modelo, Connection conn) throws SQLException;
    void eliminar(ID id, Connection conn) throws SQLException;
}

// daoimpl/TransaccionDAOImpl.java
package patitasarriba.daoimpl;
public abstract class TransaccionDAOImpl<T extends Registro> extends BaseDAOImpl<T> implements TransaccionDAO<T, Integer> {
    @Override public void crear(T modelo, Connection conn) throws SQLException { ejecutarComandoInsertar(conn, modelo); }
    @Override public void actualizar(T modelo, Connection conn) throws SQLException { ejecutarComandoActualizar(conn, modelo); }
    @Override public void eliminar(Integer id, Connection conn) throws SQLException { ejecutarComandoEliminar(conn, id); }
}

Resultado: mvn package sin saltar tests y DAORefactorChecks imprime DAO checks passed: 10. Si el autor ya tiene sus propias versiones sin subir, usar las suyas.

2.2 Envío de correo real: GlassFish no confía en el certificado de Gmail

Síntoma: el registro muestra “No se pudo enviar el correo”.
Causa: SSLHandshakeException: PKIX path building failed. El truststore del dominio (domains/domain1/config/cacerts.p12) trae solo 2 certificados y no incluye GlobalSign, raíz de la cadena de Gmail. Desde una JVM normal la misma conexión funciona.
Corrección en Avances/patitasarriba-negocio/src/main/java/patitasarriba/blimpl/correo/CorreoSmtp.java: usar los certificados del JDK. Una línea cambia en enviar y se agrega un método:

- try (SSLSocket socket = (SSLSocket) SSLSocketFactory.getDefault().createSocket(host, puerto)) {
+ try (SSLSocket socket = (SSLSocket) fabricaConfianza().createSocket(host, puerto)) {

+ static SSLSocketFactory fabricaConfianza() {
+     try {
+         File cacerts = new File(System.getProperty("java.home"), "lib/security/cacerts");
+         KeyStore raices = KeyStore.getInstance(cacerts, "changeit".toCharArray());
+         TrustManagerFactory confianza = TrustManagerFactory.getInstance(TrustManagerFactory.getDefaultAlgorithm());
+         confianza.init(raices);
+         SSLContext contexto = SSLContext.getInstance("TLS");
+         contexto.init(null, confianza.getTrustManagers(), null);
+         return contexto.getSocketFactory();
+     } catch (Exception e) {
+         return (SSLSocketFactory) SSLSocketFactory.getDefault();   // como antes si no se pueden leer
+     }
+ }

Imports nuevos: javax.net.ssl.SSLContext, javax.net.ssl.TrustManagerFactory, java.io.File, java.security.KeyStore. También se reemplazó el comentario “no se probó contra un servidor real”.

3.1 Components/Pages/Seguridad/LoginPage.razor: el aviso queda pegado mientras se escribe

Síntoma: tras dejar la contraseña vacía, “La contraseña es obligatoria” sigue visible aunque ya se esté escribiendo (hasta salir del campo). El login sí funciona.
Corrección: en los dos InputText (correo y clave) se agrega un @oninput que actualiza el modelo y revalida solo si ya había un aviso:

<InputText id="clave" ... @bind-Value="ViewModel.Password"
           @oninput="e => AlEscribir(nameof(LoginViewModel.Password), e)" @onblur="..." />

private void AlEscribir(string campo, ChangeEventArgs e) {
    string texto = e.Value?.ToString() ?? "";
    if (campo == nameof(LoginViewModel.Correo)) ViewModel.Correo = texto; else ViewModel.Password = texto;
    FieldIdentifier campoActual = new FieldIdentifier(ViewModel, campo);
    if (Contexto.GetValidationMessages(campoActual).Any()) Contexto.NotifyFieldChanged(campoActual);
}
No usar @bind-Value:event="oninput" en InputText ni en los PaInput*. Tira el circuito de Blazor con ChangeEventArgs cannot be converted to System.String y el formulario se envía como POST nativo (“The POST request does not specify which form is being submitted…”). Es la “pantalla negra” de Nuevo artículo que ya corrigió Leonardo.

4 · Activar el correo real (sin guardar credenciales en el repo)

El código lee variables de entorno del proceso de GlassFish. Si falta alguna de las tres primeras, el correo se imprime en el log (modo consola).

VariableValor
PATITAS_SMTP_HOSTsmtp.gmail.com (fijo)
PATITAS_SMTP_USUARIOel Gmail que envía
PATITAS_SMTP_CLAVEcontraseña de aplicación de 16 letras, sin espacios (requiere verificación en 2 pasos; se crea en myaccount.google.com/apppasswords)
PATITAS_URL_FRONT (opcional)por defecto http://localhost:5118
[Environment]::SetEnvironmentVariable("PATITAS_SMTP_HOST","smtp.gmail.com","User")
[Environment]::SetEnvironmentVariable("PATITAS_SMTP_USUARIO","TU_CORREO@gmail.com","User")
[Environment]::SetEnvironmentVariable("PATITAS_SMTP_CLAVE","LA_CLAVE_SIN_ESPACIOS","User")

Después: cerrar IntelliJ por completo, abrirlo y reiniciar GlassFish (las variables se leen al arrancar). Cada persona configura las suyas; la clave no se sube ni se pega en grupos.

5 · Cómo comprobar que funciona

  1. Build: cd Avances; mvn -q package sin errores, y DAORefactorChecks = DAO checks passed: 10.
  2. Login: con los campos vacíos pulsar Ingresar (aparecen avisos) y escribir: el aviso desaparece al teclear. Contraseña mala → “Correo o contraseña incorrectos”.
  3. Enlaces: /registro y /olvide-contrasena muestran un solo “← Volver al inicio de sesión”.
  4. Correo: /registro con un correo real distinto del remitente → llega “Confirma tu correo - Patitas Arriba” (revisar Spam) → abrir el enlace en la misma PC que corre el front → “¡Tu cuenta quedó activa!”.

6 · Problemas conocidos (no corregidos)

QuéDetalle
Enlace del correo con localhostAbre solo en la PC que corre el front. Desde un celular necesita PATITAS_URL_FRONT=http://IP_DE_LA_PC:5118, el front con --urls http://0.0.0.0:5118 y el puerto abierto en el Firewall.
Teléfono o DNI de un cliente dado de bajaLa validación ignora a los clientes con activo=0 pero el UNIQUE de MySQL no. El registro avisa “Revisa tu correo” y al confirmar falla con “No se pudo completar el registro” (Duplicate entry … telefono_UNIQUE). Propuesta: validar contra todos los registros y dar un mensaje claro.
Número de boletaSe asigna fuera de la transacción: dos emisiones simultáneas podrían chocar. Propuesta: asignarlo dentro de la transacción.
Solo puerto 465CorreoSmtp usa TLS implícito; Outlook/Hotmail (587, STARTTLS) no funcionan.
